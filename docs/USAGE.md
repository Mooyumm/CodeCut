# CodeCut 使用指南

[返回首页](../README.md) · [AI 接入与开发建议](AI_INTEGRATION.md)

## 1. 安装与准备

### 下载运行

从 [Releases](https://github.com/Mooyumm/CodeCut/releases) 下载 `CodeCut-macOS-arm64.zip`，解压并将 `CodeCut.app` 拖入「应用程序」。当前包只面向 Apple Silicon / macOS 15+，没有 Developer ID 签名和 Apple 公证。若系统阻止运行，可选择从源码构建；不要把本地备份包当作已经完成公证的安装器。

Release 同时提供源码 ZIP、Git 历史 bundle、源码提交号和 SHA256 清单。把附件放在同一目录，执行 `shasum -a 256 -c SHA256SUMS.txt` 可检查完整性。下载包对应其标注的提交，可能早于主分支文档更新。

### 从源码运行

```sh
git clone https://github.com/Mooyumm/CodeCut.git
cd CodeCut
open CodeCutMac/CodeCut.xcodeproj
```

选择 `CodeCut` / `My Mac`，按需把签名团队改成自己的团队，然后运行。没有分发证书也可在源码根目录执行 `bash CodeCutMac/scripts/package.sh` 构建 ad-hoc 签名版。打包脚本用当前工作区编译，但源码 ZIP 来自 HEAD，因此先提交需要包含的修改。

### 初次准备 AI

1. 打开应用的 AI 设置。
2. 点击「准备本地模型」，等待运行时与视觉模型权重下载完成。
3. 点击「检查状态」，再点「测试连接」。首次加载较慢，避免连续重复发起任务。
4. 第一次点击「转写」时，WhisperKit 会准备自己的语音模型，这与视觉模型是两套资源。

不需要填写云端 API Key。首次下载需要网络与足够磁盘空间；模型准备好之后可以离线推理。代码默认 Qwen3-VL 8B，GGUF 与视觉投影文件合计约 5.8 GB（十进制）；4B 配置约 3.0 GB。文件大小不等于运行内存，还需为系统、视频与模型缓存留出空间。

## 2. 创建项目与导入资料

通过「文件 → 新建项目… / 打开项目… / 导入素材到当前项目…」操作。视频导入后成为项目素材；各项目保存自己的文字稿、AI 对话、文稿、分镜表和剪辑决定。

在「文稿」工作区整理：

- 产品 brief：支持 PDF、DOCX、PPTX、图片、RTF、HTML、纯文本；老式 DOC / PPT 依赖系统转换，复杂排版可能需要手工核对。
- 口播稿：填入实际要读或已录制的稿子，帮助字幕断句与审阅。
- 产品参考图：确认提取出的产品款式、颜色和图片是否正确。
- 分镜稿：按表格逐行编写，或导入 CSV；常用列为文稿、分镜、镜头类型、是否拍摄、备注。

分镜表可编辑单元格，拖动边缘调整列宽与行高，右键插入或删除行列。文稿和分镜工作区共享同一份分镜数据。

## 3. 转写与口播精剪

1. 在「口播」工作区点击「转写」，等待逐词时间戳与文字稿出现。相同素材和配置可复用缓存。
2. 播放核对识别文本，修正人名、产品名与数字。
3. 用「重新断句」按文稿标点和真实停顿整理字幕。它不调用语言模型；修改文稿后需主动重新断句。
4. 选择词语或字幕范围进行删除、编辑、拆分与合并。删词后通过跳过删除区间预览效果。
5. 按需要设置停顿、头尾、气口和去重选项。检查 AI 审阅建议再接受，重复内容可明确保留。
6. 在时间线上拖动播放头、入点和出点，试听每个衔接，使用撤销 / 重做修正取舍。

本地匹配以真实逐词时间为依据；AI 文本建议不能代替试听。尤其注意误删否定词、数字或保留了错误的重复版本。

## 4. B-roll 与分镜

1. 进入「B-roll」导入实拍素材，检查素材是否齐全。
2. 运行画面或产品识别；核对产品参考图、主体、推荐区间及待确认物品。
3. 左栏查看全部素材，右栏按识别产品归类；同一素材可出现在多个产品分组中，不会复制原视频。
4. 通过搜索、产品档位或待确认筛选找到素材；点击时间码回到对应画面核对。
5. 在「分镜」里点「匹配口播时间」，将分镜稿台词匹配到剪辑后的时间。口播没有说到的行可能留空。
6. 点击「AI 排 B-roll」，系统先筛选候选，再由本机模型挑选。没有合适素材的镜头允许留空；标记为未拍摄或网络素材的镜头不从本地库硬配。
7. 查看实际轨道、起点、素材尾部及重叠情况；当前排片可延续至素材末尾，不保证与台词时长完全一致。可「清除排片」或撤销。

生成分镜制作提示词用于后续设计、动效或生成工具，不会在当前版本内自动调用视频生成服务。

## 5. 音乐参考库

音乐参考库跨项目保存，与某个视频项目的剪辑记录分开。

1. 导入 MP3、WAV、M4A、AIFF 等音频。导入会复制到参考库，原文件保留。NCM 需要额外解码组件。
2. 空格播放 / 暂停，点击波形定位；按 `I` 设置入点，`O` 设置出点，循环试听选区。编辑文字时不会触发这些快捷键。
3. 点击「确认片段」，为每段添加批注；同一首音乐可以保存多段、允许重叠。
4. 将音乐与片段拖到目录树文件夹归档，右键重命名、移动或删除。
5. 已装好音频环境时，点「读取音乐」得到音频特征和 Qwen 描述；点「AI 分类并生成提示词」结合描述与批注整理用途和提示词。
6. 「导出片段」输出 M4A、TXT 批注和 JSON。播放器「去人声」需要 AudioForge 模型环境，会生成独立伴奏副本。

Essentia 支持 1–600 秒片段；BPM / 调性在不少于 10 秒时才尝试估计，近静音可能跳过。Qwen2-Audio 只分析所选片段前 30 秒。乐器、情绪与人声描述属于模型推断；BPM 与调性属于算法估计。Qwen 分析期间，本应用暂停去人声任务，结束后恢复；被中断的分离任务会从头计算。

### 可选依赖配置

这些组件不是主应用的内置安装器内容。基础剪辑无需先把音乐 AI 全部装好。

| 功能 | 运行条件 |
| --- | --- |
| 普通音频入库、选段、批注 | macOS 支持的音频文件 |
| NCM 解码 | 已安装的 AudioForge.app 内 `ncm_decode_cli.py` / `ncm_decoder.py`，以及 AudioForge Python / FFmpeg |
| 去人声 | `~/.audioforge/venv/bin/audio-separator`、FFmpeg、`~/.audioforge/models/` 中所需 BS-Roformer 模型 |
| Essentia | `~/Library/Application Support/CodeCut/Runtime/essentia-env/bin/python3` 与指定 Essentia 包 |
| Qwen 音频描述 | 独立 `qwen-audio-env`、完整 Qwen2-Audio 模型目录，以及 `~/.audioforge/venv/bin/ffmpeg` |

已有 AudioForge 环境时，Essentia 可按开发机方式建立独立环境：

```sh
RUNTIME="$HOME/Library/Application Support/CodeCut/Runtime"
"$HOME/.audioforge/venv/bin/python3" -m venv "$RUNTIME/essentia-env"
"$RUNTIME/essentia-env/bin/python3" -m pip install --only-binary=:all: 'essentia==2.1b6.dev1389'
```

若前提环境不存在，请先配置 AudioForge；本仓库不包含其安装程序。Qwen 音频适配使用 MLX 0.32.3、mlx-audio 0.5.8（固定提交）、Transformers 5.19.0 和 jinja2 3.1.6；准确提交与模型路径见 [功能详解](FEATURE_DETAILS.md)。`download_qwen_audio.py` **仅下载并校验 weights.safetensors**，不创建 Python 环境，也不下载处理器、分词器及配置文件，单独运行它不能完成全部安装。此可选功能尚无经过新机器端到端验证的一键部署流程。

## 6. 导出与继续剪辑

确认项目、剪辑区间与导出目标后选择输出：

| 输出 | 用途 |
| --- | --- |
| MP4 | 导出视频；需要画面内字幕时打开烧录字幕选项 |
| SRT | 将字幕交给播放器或其他剪辑软件 |
| FCPXML | 将剪辑结构交给支持该格式的后期软件 |
| EDL / EDL JSON | 交换剪辑决定；导入目标软件后检查素材链接、轨道和时间码 |
| CSV | 交换分镜表，不包含原视频 |

不同软件对交换格式的支持不同。导出前试听，导入后检查；交换文件不替代素材备份。

## 7. 保存、迁移与恢复

- 应用数据、视觉模型与运行时主要位于 `~/Library/Application Support/CodeCut/`。
- WhisperKit 缓存另由转写模块记录；代码也检查 `~/Documents/huggingface/models/argmaxinc/whisperkit-coreml/`，不要只复制 CodeCut 的 Application Support 就认定语音模型已经迁移。
- 音乐参考库默认在 `~/Library/Application Support/CodeCut/MusicReferences/`。可在音乐参考的设置里更改位置，迁移成功后原目录保留备份。
- 项目原视频被移动后，重新打开项目按提示定位文件。备份时连同原始素材与项目文件一起保存。
- 参考库 `library.json` 损坏会尝试 `library.backup.json`；两者都不可读时停止写入，避免覆盖。
- 删除音乐会将该参考库副本及关联内容移到废纸篓；删除前确认名称和片段数量。原导入来源文件不受影响。

## 8. 常见问题

| 现象 | 检查方式 |
| --- | --- |
| 应用不能打开 | 核对 Apple Silicon / macOS 15+；当前下载包未公证，可从源码构建 |
| 本地模型未就绪 | 检查下载、磁盘空间与设置里的状态；查看 `~/Library/Application Support/CodeCut/llama-server.log` |
| 首次转写很慢 | 区分语音模型下载、加载和实际转写；首次完成后会缓存 |
| AI 速度慢或内存紧张 | 减少并行 AI 任务；4B 配置需代码或偏好设置支持，当前 AI 设置页没有通用模型服务选择器 |
| 音乐分析 / 去人声失败 | 核对上表中独立环境、FFmpeg、模型与配置文件；基础 App 包不包含它们 |
| 找不到 API Key 输入框 | 当前关闭云端接口，属于预期行为 |
| B-roll 没有匹配上 | 核对资料、识别结果和台词；没有合适候选允许留空 |
| 在网页运行缺少完整功能 | 根目录网页仅为历史原型，请运行原生应用 |

报告问题时请附脱敏日志与复现步骤。不要在公开 Issue 中提交私密项目、素材或令牌。
